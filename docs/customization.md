# Настройка ссылок Bitrix24 Quick Links

Версия `1.1.0` не требует добавлять домен портала в исходники или манифест. Откройте нужный Bitrix24, нажмите значок расширения и активируйте текущий адрес.

## Пользовательская настройка

Рекомендуемый способ:

1. Откройте **Быстрые ссылки**.
2. Нажмите шестеренку.
3. Выберите **Редактор ссылок**.
4. Добавьте блоки, обычные кнопки или вложенные окна.
5. Сохраните изменения и экспортируйте JSON как резервную копию.

Настройки хранятся отдельно для каждого активированного портала.

## Внутренние и внешние ссылки

Для страницы текущего Bitrix24 используйте относительный путь:

```text
/crm/deal/kanban/
```

Расширение автоматически добавит текущий адрес портала. Такая кнопка работает после переноса конфигурации между облачным и коробочным Bitrix24.

Для стороннего сайта укажите полный HTTPS-адрес:

```text
https://example.com/help/
```

## Шаблоны открытия по ID

В шаблоне используется параметр в фигурных скобках:

```text
/crm/deal/details/{id}/
```

Стандартные шаблоны новой установки находятся в блоке **Открыть по ID**.

## Стартовая конфигурация разработчика

Базовый набор расположен в:

- `src/chromium/settings.js`;
- `src/firefox/settings.js`.

Используйте относительные пути для всех внутренних страниц. Домены в `legacyPortalHosts` нужны только для миграции настроек версии `1.0`; добавлять туда новые порталы не требуется.

После изменения стартового набора синхронизируйте браузерные версии, пересоберите Safari и запустите проверки:

```bash
npm run build:safari
npm test
npm run test:ui
```

Не публикуйте пароли, токены, приватные вебхуки и ссылки с секретными параметрами.

## Перенос версии 1.0

При первом открытии прежнего портала расширение переносит старую конфигурацию в отдельное хранилище этого адреса. Известные абсолютные ссылки OSTEC и Selectica преобразуются в относительные пути.

Импорт старого JSON учитывает `portalHosts`, `defaultPortalHost` и `portalOrigin`. Перед обновлением рекомендуется сохранить дополнительный экспорт настроек.
