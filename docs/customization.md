# Адаптация под другой портал Bitrix24

Готовые пакеты ограничены доменами, перечисленными в манифестах. Это снижает объем разрешений расширения. Для своего коробочного портала соберите отдельный вариант.

## 1. Добавьте домен

Внесите домен без протокола в `portalHosts`:

- `src/chromium/settings.js`;
- `src/firefox/settings.js`.

Если новый портал должен быть базовым для ссылок, измените `defaultPortalHost` в обоих файлах.

## 2. Обновите разрешения браузеров

Добавьте шаблон `https://example.bitrix24.ru/*` в оба раздела `matches` и в `host_permissions`:

- `src/chromium/manifest.json`;
- `src/firefox/manifest.json`.

Используйте только те домены, на которых расширение действительно должно работать.

## 3. Настройте стартовые ссылки

Измените массив `sections` в `settings.js`. Для каждой кнопки укажите понятное название и полный HTTPS-адрес. Структуру вложенных окон можно посмотреть в существующих блоках CRM.

Не публикуйте в репозитории пароли, токены, приватные вебхуки и ссылки с секретными параметрами.

## 4. Обновите Safari

Добавьте URL-шаблон портала в `PORTALS` файла `tools/build-userscripts.js`, затем выполните:

```bash
npm run build:safari
npm run test:safari
```

Команда пересоберет оба userscript-файла в `releases/1.0/safari`.

## 5. Проверьте сборку

```bash
npm test
npm run test:ui
```

После установки проверьте на целевом портале:

1. появление кнопки в левом меню;
2. открытие основного окна и вложенных окон;
3. поиск и избранное;
4. открытие ссылки обычным и средним кликом;
5. импорт и экспорт JSON;
6. сохранение состояния блоков после обновления страницы.

## Хранение пользовательских настроек

- Chromium использует локальное хранилище расширения;
- Firefox использует `localStorage` текущего портала;
- Safari Userscripts использует `GM.getValue` и `GM.setValue`.

Перед переустановкой или сменой идентификатора расширения экспортируйте настройки в JSON.
